# College Bound DOCX → HTML workflow

This package implements the new 2026–2027 College Bound workflow: the monthly issue starts as a Word `.docx`, is converted to responsive HTML, and is linked from the Current Issues page. The completed 2025–2026 year remains a PDF archive.

## Files

- `convert_issue.py` — conservative DOCX → HTML converter.
- `issue.css` — shared College Bound newsletter design, based on the 2025–2026 PDF samples but adapted for scrolling/mobile.
- `verify_issue.py` — basic QA check for generated HTML.
- `build_issue.bat` — Windows helper.
- `Sept26.html` — generated September 2026 mockup from the supplied Word file.
- `CURSOR_PROMPT.md` — copy/paste implementation prompt for Cursor.
- `ROLLOVER_CHECKLIST.md` — site/FTP rollout sequence.

## One-time setup

```bash
py -m pip install -r requirements.txt
```

## Convert an issue

```bash
py convert_issue.py "CB926.rcs.docx" "Sept26.html" --css issue.css
```

or on Windows:

```bat
build_issue.bat "CB926.rcs.docx" "Sept26.html"
```

For October, for example:

```bash
py convert_issue.py "CB1026.docx" "Oct26.html" --css issue.css
```

## QA

```bash
py verify_issue.py Sept26.html --expect-volume "Vol. 41, No. 1" --expect-date "September 2026"
```

Then open `Sept26.html` in Chrome and inspect both desktop and mobile widths.

## Production placement

Recommended 2026–2027 structure:

```text
/members/26-27issues/
    articles.php
    issue.css
    Sept26.html
    Oct26.html
    Nov26.html
    ...
```

`articles.php` should link September 2026 to `Sept26.html`, **not** `Sept26.pdf`.

## Design intent

The PDFs establish the visual language: large light-blue italic “College Bound” masthead, uppercase spaced tagline, small volume/date row, black rules, serif editorial copy, blue section bars, and thin newsletter-style borders. The HTML keeps those cues while changing the body to a responsive scrolling layout. It deliberately does not force a four-page/three-column PDF geometry onto a phone.

## Converter rules

The converter does not rewrite editorial content. It:

1. Reads the intro, masthead line, volume, date, and `BELOW` list.
2. Detects recurring all-caps section headings.
3. Preserves Word paragraph order.
4. Uses blank lines to group story blocks.
5. Preserves bold, italic, underline, and actual Word hyperlinks.
6. Auto-links plain `http://`, `https://`, and `www.` URLs.
7. Uses the shared `issue.css` for presentation.

If a future Word file is formatted very differently, update the parser rules instead of manually rebuilding the issue in HTML.
